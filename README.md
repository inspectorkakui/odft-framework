# ODFT Framework: Outcome-Driven Fine-Tuning for LLM Agents

A framework for training language model agents through a combination of Reinforcement Learning (RL) and Supervised Fine-Tuning (SFT).

## Core Concept

ODFT implements a novel approach that leverages heuristically-derived supervision signals from RL experiences to guide LLM fine-tuning. This hybrid approach allows for faster learning and better performance compared to traditional RL methods.

### Mathematical Formulation

Our learning process can be described mathematically in terms of the Supervised Fine-Tuning objective, where the "supervision" signal is dynamically generated by our heuristic function (`_format_experience_for_sft`):

- **s_t**: The state of the environment (market data, position info, etc.) at time t.
- **p_t = G_prompt(s_t)**: The prompt text generated by the `_prepare_prompt` function based on the state s_t.
- **π_θ**: The LLM agent's policy (parameterized by θ), which generates an action string a_t^str given a prompt p_t.
- **e_t = (s_t, p_t, a_t^str, outcome_t, benchmarks_t, ...)**: An experience tuple recorded after taking action a_t^str in state s_t.
- **F(e_t) = τ_t**: The complex, heuristic function that takes an experience e_t and generates the target SFT text string τ_t.
- **P_θ(τ_t|p_t)**: The probability assigned by the current LLM policy π_θ to generating the entire target sequence τ_t when prompted with p_t.
- **D**: The replay buffer storing past experiences {e_i}.
- **B**: A batch of experiences sampled from D.

The objective of the `agent.update()` step (using SFTTrainer) is to minimize the negative log-likelihood (cross-entropy loss) of the target sequences τ_t generated by our heuristic function F, given the corresponding prompts p_t, averaged over the sampled batch B:

```
min_θ L(θ;B) = min_θ E_{e_t~B} [-log P_θ(F(e_t)|G_prompt(s_t))]
```

In simpler terms:
- The input is the prompt generated from the environment state.
- The target output is the "correct action + reasoning" string constructed by our complex `_format_experience_for_sft` function.
- The learning objective is to adjust the LLM's parameters θ to make it better at generating these target outputs when given the corresponding inputs.

The "Reinforcement Learning" aspect comes from the fact that the data used for this supervised learning (e_t) is generated through the agent's interaction with the environment, and the construction of the target output τ_t by the function F is heavily dependent on the outcomes (rewards, status) of those interactions.

## Installation

1. Clone the repository:
```bash
git clone https://github.com/inspectorkakui/odft-framework.git
cd odft-framework
```

2. Create and activate a virtual environment:
```bash
python -m venv .venv
# On Windows
.venv\Scripts\activate
# On Linux/Mac
source .venv/bin/activate
```

3. Install the required dependencies:
```bash
pip install -r requirements.txt
```

4. Optional: Install Unsloth for faster fine-tuning (recommended for LLM agents):
```bash
pip install 'unsloth[colab-new] @ git+https://github.com/unslothai/unsloth.git'
```

## Quick Start

1. Configure your experiment in `config/examples/your_example.yaml`
2. Run the example:
```bash
python -m odft_framework.examples.your_example.main_loop
```

## Configuration Guide

ODFT uses a hierarchical YAML configuration system:

1. **Framework defaults**: `config/framework/defaults.yaml`
2. **Example-specific configs**: `config/examples/your_example/your_example.yaml`

### Key Configuration Sections

#### Run Configuration
```yaml
run:
  mode: "train"  # Options: "train", "evaluate" 
  checkpoint_to_load: null  # Path to checkpoint for resuming or evaluation
  num_episodes_train: 100  # Number of episodes for training
  num_steps_train: null  # Alternative: train for fixed number of steps
  num_episodes_eval: 10  # Number of episodes for evaluation
```

#### Environment Configuration
Environment-specific settings, for example:
```yaml
environment:
  # Your environment-specific configuration
  simulation_mode: "historical"
  initial_capital: 100.0
  # ... other environment parameters
```

#### Agent Configuration
```yaml
agent:
  # LanguageModelAgent specific settings
  model:
    base_model_name: "unsloth/mistral-7b-instruct-v0.2-bnb-4bit"
    load_in_4bit: True
    torch_dtype: "bfloat16"
    token_limit: 2048
  
  # QLoRA settings for fine-tuning
  qlora:
    r: 8
    alpha: 16
    dropout: 0.1
    target_modules: ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]
    # ... other qlora parameters
  
  # Text generation parameters
  generation:
    max_new_tokens: 20
    temperature: 0.3
    top_p: 0.9
    do_sample: True
  
  # Data preparation/prompt templates
  data_prep:
    market_template: |
      # Your template here...
```

#### Memory Configuration
```yaml
memory:
  type: "ReplayMemory"  # Options: "ReplayMemory", "AdaptiveMemoryBuffer"
  capacity: 10000
  # AdaptiveMemoryBuffer specific settings (if applicable)
  alpha: 0.6
  beta_start: 0.4
  # ... other memory parameters
```

#### Trainer Configuration
```yaml
trainer:
  max_steps_per_episode: 1000
  eval_frequency_episodes: 10
  save_frequency_episodes: 20
  update_batch_size: 64
  # ... other trainer parameters
```

## Framework Architecture

ODFT consists of several key components:

1. **Agents**: Implementations of decision-making entities
2. **Environments**: Simulations or real-world interfaces
3. **Memory**: Experience storage and replay mechanisms
4. **Trainer**: Orchestration of the training loop
